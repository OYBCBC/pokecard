# 用宝可梦素材改造热门游戏 —— 可行性与技术分析报告

> **报告日期**：2026-10-27
> **研究背景**：2025–2026 年，"热门玩法 × 宝可梦素材"的免费同人游戏连续引爆（PokéBonk、Pokemon Arena 2D、Pokémon Emerald Arena 等），验证了一条低成本、高传播的"玩法嫁接"路径。本报告复盘这些案例，并评估**再选一个热门游戏、用宝可梦素材改造**的可行性与技术方案。
> **信息来源**：游戏官网实时抓取、开发者发布帖、GitHub 仓库、媒体报道（Dexerto、GamesIndustry.biz、IGN、VGC 等）。一手信息与二手推断在文中分别标注；所有链接见附录 A。

---

## 一、执行摘要

| 维度 | 评级 | 一句话结论 |
|---|---|---|
| 产品/传播可行性 | ★★★★★ | 模式已被三款游戏连续验证：免费 + 浏览器即点即玩 + 熟 IP × 新玩法 = 天然病毒式传播 |
| 技术可行性 | ★★★★☆ | 单人开发者即可完成（两个案例都是单人）；素材、数值数据、引擎方案全部有现成社区供给 |
| 法律可行性 | ★★★☆☆ | 最大且不可消除的风险。宝可梦著作权/商标归任天堂系公司，但"非商业、不分发官方资产、免费、随时可下架"是社区通行做法，执法历史上是**选择性**的 |
| 团队/运营可行性 | ★★★★☆ | MVP 6–8 周（单人）；社区共创机制（周投票、任务）可大幅降低内容生产压力 |
| **总体判断** | **可做** | 作为**免费同人项目**可行性高；想长期商业化必须预留"一键换皮"能力，走"玩法验证 → 换原创 IP → 商用"路线（Loomian Legacy 模式） |

**三条核心结论**：

1. **玩法可以抄，素材才是红线。** 任天堂对 Palworld 打的是"玩法专利"官司，打到 2026 年中接近草草收场（预计赔偿仅约 3 万美元，远低于诉讼成本）；而对**直接使用宝可梦形象**的同人游戏，历史上用的是 DMCA 下架而非诉讼——被下架即终结，但不会倾家荡产。所以真正的风险管理点是：不商业化和不分发官方文件，而不是"玩法像不像"。
2. **浏览器是最佳载体。** 三款爆火案例全部免下载、免安装、点链接即玩，这是病毒传播系数最大的形态，也天然规避了 App Store / Steam 的上架审核与下架风险。
3. **"可换皮"是最重要的架构决策。** 把宝可梦素材、数值数据全部做成与代码分离的数据层，一旦收到律师函可在 48 小时内切换成原创怪物包——这既是法律保险，也是未来商业化的唯一通路。

## 二、案例研究：三款爆火宝可梦改版游戏

### 2.1 PokéBonk —— 现象级案例：Megabonk（3D 割草肉鸽）× 宝可梦

**基本情况**

| 项目 | 内容 |
|---|---|
| 形态 | 免费浏览器 3D 幸存者类（survivors-like）肉鸽，免下载免安装 |
| 官网 | pokebonk.com（另有同名姊妹项目 pokebonk.solais.cloud，见下文"撞名现象"） |
| 作者 | Charcher（独立开发者），2026-10-14 在 X 上公布，先跑了一周平衡性 Beta |
| 玩法模板 | 明确自述"强烈致敬 Megabonk"（vedinad 开发、2025-09 上线 Steam 的爆款，两周销量破 100 万份、峰值同时在线约 11.7 万人） |
| 规模 | 对外宣传覆盖全部 151 只关都宝可梦；第三方统计注册玩家 18.1 万+，媒体称相关内容曝光超 2 亿（均为第三方数据，未经官方确认） |
| 商业模式 | 完全免费 + 非营利声明 + 自愿捐助链接；开发者公开承认开发中使用了 AI 工具 |
| 媒体扩散 | Dexerto（2026-10-18）等游戏媒体报道后破圈；Instagram/TikTok 二创扩散 |

**玩法设计拆解**（对"玩法嫁接"最有参考价值的部分）：

- **保留了"训练家不直接操作战斗"的原设定**：宝可梦自动攻击，玩家只管移动（跳跃/冲刺/滑翔）、走位躲弹、捡经验——这个设计决策让"宝可梦 + 割草"在世界观上自洽，是嫁接成功的关键。
- 御三家（妙蛙种子/小火龙/杰尼龟）开局，升级三选一卡牌（新招式 / 攻击强化 / 维生素），招式可进化（如火焰喷射 → 大字爆炎），保留 Mega 进化、Ultimate 大招、联盟解锁等原作钩子。
- 长线留存设计：氏族系统（成员成绩累计）、个人/地图/全球排行榜、无尽模式里程碑、Classic 模式的区域/守卫/祭祠结构。

**技术指纹**（实测抓取自游戏站点，一手信息）：

- 纯 Web 单页应用，**Vite 构建**（`modulepreload` polyfill、哈希文件名的 ES module 分包，含独立 i18n 包）。
- 3D 渲染为 **Three.js**（其 JS 资源包内含 5 处 `WebGLRenderer`，无 Unity/Godot 的 wasm 加载器特征）。
- 宝可梦以 **2D 立绘 billboard 贴在 3D 场景**中，图片按全国图鉴编号组织（`/sprites/home/{编号}.png`）——这是社区常用的 Pokemon Showdown 风格素材，用 2D 素材做 3D 游戏大幅降低了美术成本。
- 打磨细节：触屏适配、自动降分辨率、"轻/普通/锐利"画质档、三语（葡/英/西）、内置 **F2 实时平衡编辑器（JSON 导入导出，可"发布给所有人"）**——数据驱动做到极致的体现。

> **撞名现象（重要行业信号）**：PokéCommunity 上另有一个 2026-10-11 发布的同名项目（pokebonk.solais.cloud，巴西独立开发者 touchzada/Luciano Gomes，44 只可选宝可梦、6 种模式、8 人房间码联机、Boss 战、BP 货币/任务/排行榜），作者还做过 Inked（4v4 射击）、Pokémon TCG Clash 等多个浏览器 IP 游戏。此外已出现 pokebonk.run / pokebonk.co 等第三方攻略站（内容互相矛盾）。**爆款同人游戏会在数天内催生同名克隆、SEO 攻略站、域名抢注**——这既是竞争威胁，也反证了模式的传播效率。

### 2.2 Pokemon Arena 2D —— 用户所指的"宝可梦竞技场"：回合制 → 实时对战

**基本情况**

| 项目 | 内容 |
|---|---|
| 形态 | 免费浏览器俯视角 **3v3 实时对战**（非回合制），支持键鼠/手柄/触屏 |
| 原版 | 原官网 pokemonarena2d.org 曾收录为"1000+ 宝可梦、道馆 Boss、在线 1v1"的实时对战游戏（GameTop 收录描述），角色按格斗游戏式定位划分：Rushdown（强攻）/ Zoner（远程牵制）/ Tank / Speedder |
| 现状 | **原 .org 域名已失效，现打开是一个无关的 VPN 广告站**——同人游戏域名/渠道脆弱性的活教材；当前可玩的是 pokemonarena2d.online 上对原版的复刻版（自述"reimplements"另一款同人竞技场游戏） |
| 复刻版内容 | 24 只宝可梦、57 个招式、18 属性、6 张竞技场；剧情模式含 8 道馆 + 冠军之路式终局；三档难度的 CPU 对手 |

**玩法设计拆解**（实时化改造的教科书，与用户记忆中"血量 + 体力值"完全对应）：

- **双资源模型**：HP（血量）+ PP（招式次数，即"体力值"）+ 冷却时间三重资源管理，构成实时战斗的决策骨架。
- 招式 = 方向 + 判定形状（弹道/扇形/脉冲等四类）+ 射程 + 前摇（wind-up）+ 冷却 + PP 消耗——把回合制招式翻译成了格斗游戏语汇。
- 闪避带无敌帧（i-frames）；Q/E 换人，换人瞬间短暂无敌并让出场地位置。
- **可破坏掩体**：材质与属性弱点挂钩（电击岩石之类），把属性克制从数值表变成场景交互。
- 定时刷新的奖励区域：回 PP / 治疗 / 解除状态 / 重置冷却 / 刷新闪避 / 加速。
- **完整保留官方数值数学**：STAB 1.5 倍、18×18 属性克制表、暴击、能力等级、种族值上下限全部照搬——老玩家零学习成本，这是"宝可梦素材"价值最大化的核心手法。
- 状态异常（灼伤/麻痹/中毒等）实时 tick 结算。

**技术指纹与法律姿态**（一手信息，抓取自官网 FAQ）：

- 自述为 **"plain canvas app"——无任何游戏引擎的原生 Canvas 2D 单页应用**，运行时不加载外部素材、可离线游玩（PWA 式）、本地存档、无账号系统、60 FPS。
- 法律姿态声明（原文要点）："不重新分发任何来自官方游戏的美朮/精灵图/模型/音乐；素材来自其所复刻的同人游戏，后者注明来自 Pokemon Showdown 精灵图与叫声素材库并附署名；游戏代码每一行均为原创；'Pokémon'仅作描述性使用而非产品命名；若权利方要求将立即移除。"
- **评价**：这是目前同人圈最规范的法律话术模板（尽管"素材经由同人链条转手"在法理上并不能洗白著作权瑕疵，但它表明了姿态：不商业化、不碰官方文件、可随时撤）。值得整段借鉴。

### 2.3 Pokémon Emerald Arena —— ROM hack 路线：《绿宝石》实时战斗化

| 项目 | 内容 |
|---|---|
| 形态 | GBA ROM hack（基于 pret/pokeemerald **官方解包工程**），玩家用自有的正版《绿宝石》ROM 打 BPS 补丁 |
| 仓库 | GitHub GBurgardt/pokemon-emerald-arena（319 星），新增代码 MIT 协议 |
| 内容 | 实时移动/瞄准/闪避（B+方向）、可破坏岩石、瞄准投球捕捉（L+R）、HP/PP/经验持久化、187 只宝可梦的 PMD 风格动画贴图，甚至支持语音控制战斗 |
| 分发 | 只发补丁不发 ROM；自带浏览器版补丁器 `Prepare-Emerald-Arena.html`，对用户 ROM 做字节级校验 |

**技术架构（其 HOW-IT-WORKS.md，一手资料，对"改造而非重写"极具参考价值）**：

- **混合引擎**：在原版引擎外挂一层实时竞技场模块——`arena_moves.c`（招式档案）、`arena_move_fx.c`（招式效果）、`arena_navigation.c`（敌方 AI）、`arena_physics.c`（物理与可破坏物）；**伤害结算、能力变化、吸取、经验仍走《绿宝石》原生战斗例程**。实时层只加"时机与位置"，不动数值内核。
- 不支持的战斗类型（双打/联机）自动回落到原版回合制——**渐进式改造**而非全量重写。
- GBA 硬件极限下的优化：流式 tile 字典 + 双固定帧缓冲，碎片特效可让出精灵槽位，保证攻击动画永不被挤掉。

### 2.4 案例横向对比

| | PokéBonk | Pokemon Arena 2D（复刻版） | Emerald Arena |
|---|---|---|---|
| 嫁接公式 | Megabonk 割草 × 宝可梦 | 格斗/竞技场 × 宝可梦 | 原作自身实时化 |
| 载体 | 浏览器 3D | 浏览器 2D | GBA 模拟器 |
| 技术 | Vite + Three.js + 2D billboard | 原生 Canvas 2D，无引擎 | C，解包工程外挂模块 |
| 团队 | 单人（+AI 工具） | 单人（复刻版） | 单人开源 |
| 联机 | 8 人 co-op / 氏族 | 在线 1v1（原版） | 无 |
| 商业 | 免费 + 捐助 | 完全免费 | 免费 |
| 法律姿态 | 免责声明 + 非营利 | 不分发官方资产声明 + 随时可删 | 只发补丁，不分发 ROM |

### 2.5 成功要素提炼（可直接复用）

1. **认知零成本**：玩法（割草/格斗）玩家已会，IP（宝可梦）玩家已爱，属性克制/招式体系现成——内容和数值系统几乎"零创作成本"。
2. **反差新鲜感**：回合制 IP × 实时/肉鸽玩法，天然出短视频名场面（极限闪避、疯狂 Build、Mega 进化瞬间）。
3. **零摩擦分发**：浏览器点开即玩、免下载免注册（游客模式），链接本身就是传播单元。
4. **保留官方数值**：STAB、克制表、种族值照搬，老玩家肌肉记忆直接迁移。
5. **内容逐步放量**：首发 24–44 只 + 每周社区投票加新角色，把内容生产变成运营事件。
6. **元游戏留存**：任务、排行榜、货币解锁、赛季/周常。
7. **单人 + 数据驱动可维护**：实时平衡编辑器（JSON 热更）让一个人能运营一个"在线服务游戏"。
8. **克制的技术选型**：无引擎或轻引擎、2D 素材进 3D 场景，把工期花在手感与内容上。

## 三、"改造哪个游戏"：候选方向评估

选题公式：**X（已被验证的热门玩法内核）× 宝可梦（素材与数值皮）× 浏览器（零摩擦分发）**。约束：避开官方已有强势品类，避开已被同人爆款占位的方向，单人 3–4 个月内可交付。

| 候选方向 | 现有占位情况 | 素材契合 | 单人开发量 | 差异化空间 | 传播性 | 法律敏感度 | 综合建议 |
|---|---|---|---|---|---|---|---|
| 3D 割草肉鸽（Megabonk/吸血鬼幸存者） | **PokéBonk ×2、Pokey Survivors 已占** | ★★★★★ | 中 | ★（红海） | ★★★★★ | 中 | ❌ 避开 |
| 俯视角实时竞技场（3v3/1v1） | Pokemon Arena 2D 已占 | ★★★★★ | 中 | ★★ | ★★★★ | 中 | ❌ 基本避让 |
| **自走棋/酒馆战棋**（TFT/野猪棋式） | 仅 Dota2/SC2 社区地图级作品，无浏览器爆款 | ★★★★★（属性/特性/进化=升星，天然棋子） | **中低**（回合制，无实时手感调校成本；异步对战可规避联机同步难题） | ★★★★ | ★★★★ | 中低 | ✅ **首选** |
| Balatro 式肉鸽卡牌构建 | PokéBonk 作者的 TCG Clash 试水过卡牌；官方 PTCG 是对战卡牌，非肉鸽 | ★★★★（徽章/招式=牌） | 中 | ★★★★ | ★★★★★（胡牌短视频传播力极强） | 中（卡牌是官方核心商业领域，需更保守） | ✅ 次选 |
| Suika/合成大西瓜物理合成 | 微信小游戏圈大量克隆 | ★★★★★ | **低**（2–3 周 demo） | ★ | ★★★★ | 低 | ⚠️ 快但难留存，适合练手 |
| 多人物理乱斗（Party Animals/糖豆人） | 官方无此品类 | ★★★（需 3D 模型） | 高（联机+物理） | ★★★★ | ★★★★★ | 中 | ⚠️ 团队 ≥3 人才考虑 |
| 社交推理（Among Us 式） | 极少 | ★★ | 中 | ★★★★ | ★★★★ | 低 | ⚠️ 依赖 simultaneous 在线人数 |
| 生存制造（Palworld 式） | — | ★★★★ | 极高 | ★★★ | ★★★★★ | **极高（任天堂正主诉讼进行中，虽然其收场疲软）** | ❌ 禁止 |
| 官方在运营品类（MOBA/Snap/PTCG 对战） | Unite / Snap / PTCG Live | — | — | — | — | 高 | ❌ 避开 |

**推荐路线：自走棋/酒馆战棋 × 宝可梦**，理由：

- 素材契合度满分类：宝可梦的**属性克制（阵容搭配）、特性（棋子被动）、进化链（一星→二星→三星的现成叙事）**天然就是自走棋系统；数值数据（种族值/招式/特性）可从社区数据源直接生成棋子面板。
- 回合制 = 单人可做的最大保证：不需要实时手感调校（那是最耗时、最依赖天赋的部分），异步 PvP（打对面快照阵容）可完全规避实时 netcode。
- 该品类尚无"浏览器即玩、免费、长线运营"的宝可梦爆款——位置是空的。
- 中文市场窗口：现有爆款均无中文（英/西/葡），B 站/抖音的宝可梦二创生态巨大，中文首发是现成的差异化。

## 四、可行性分析

### 4.1 产品与传播可行性：高

- **先例充分**：PokéBonk 三周内 18 万注册玩家、主流游戏媒体报道；Pokemon Arena 2D 火到被复刻、被抢注域名；Megabonk 证明玩法内核本身有百万级受众。
- **传播链路成熟**：PokéCommunity / r/pokemon / Discord 首发 → TikTok/Instagram/YouTube Shorts 二创 → Dexerto 类"同人游戏新闻"栏目放大 → 国内 B 站/抖音搬运。游戏媒体对宝可梦同人游戏已有固定报道习惯，等于免费的 PR 管道。
- **风险提示**：热度窗口短（数周到数月），同名克隆会在几天内出现；需在首发时就准备好 Discord 认证渠道与版本签名，并在 X/YouTube 建立官方身份。

### 4.2 法律与 IP 风险：核心约束（可管理、不可消除）

**权利结构**：宝可梦的著作权与商标权分属任天堂、Game Freak、Creatures 及 The Pokémon Company（四家共同持股 IP）。涉及的责权有三层：

1. **著作权（最大风险）**：精灵形象、叫声、音乐、名称文本。任何直接使用都构成侵权，"非商业"不构成豁免，只是降低被追究的概率。
2. **商标（中风险）**："Pokémon/宝可梦"及精灵名是注册商标。案例中通行的缓解做法是：标题使用需可辩护为描述性使用（如 "Pokemon Arena 2D" 实际上已在打擦边球）、页脚放"宝可梦 © Nintendo/Creatures/Game Freak，本作为非官方同人作品"声明。
3. **专利（低概率、高杀伤）**：任天堂 2024-09 对 Palworld 发起的是**玩法专利**诉讼（捕捉机制等三项日本专利），寻求禁令与赔偿。到 2026 年中，该案被多路媒体报道为接近"无疾而终"：IP 专家估算即使胜诉赔偿也仅约 3 万美元（IGN/VGC），而任天堂年报被指披露诉讼相关损失约 4000 万美元（GamesFray，未经官方逐项确认）。**结论：玩法相似本身风险有限且任天堂该路径收效差；对个人开发者真正的风险是"被起诉的应诉成本"而非败诉金额**——所以非商业、小体量反而是事实上的保护色。

**执法模式（历史先例，公开报道）**：

- 被 DMCA 下架的：Pokémon Uranium（2016，发布约十天内，此前已 150 万下载）、Pokémon Prism（2016，发布前夜）、Pokémon Brick Bronze（2017，Roblox 下架，团队其后转型原创 IP 的 Loomian Legacy 并成功商业化）、Pokémon Essentials 引擎本身（2018）、Pixelmon（Minecraft 模组，2017，后以分支形式复活）。
- 长期存活至今的：Pokémon Showdown（对战模拟器）、PokeAPI（公开分发精灵图与数据）、Reborn/Rejuvenation/Insurgence/Radical Red 等大量同人 RPG、以及本报告的全部三个案例（截至 2026-10 均未被下架，PokéBonk 甚至有 18 万玩家和媒体报道）。
- **规律**：打击集中于 ①商业化（收费/广告/内购）②直接分发 ROM 或官方资产 ③在官方产品发布窗口期高调抢风头。非商业、免费、只发原创代码与补丁、不捆绑官方文件的项目长期处于"被容忍的灰色地带"。

**平台与渠道风险**：

- Steam/itch.io：会响应 DMCA，且上架本身即"商业化"信号，不建议。
- 自有域名 + 静态托管（Cloudflare Pages 等）：最稳路径，但**域名会失效/被抢注**（Pokemon Arena 2D 的 .org 已沦为 VPN 广告站是现成教训）——需域名自动续费、多镜像、提供可下载的离线包。
- 国内分发：无备案的境外托管在国内可达性不稳，需考虑镜像与网盘兜底；另注意国内平台对宝可梦同人内容的处理不确定性更高。

**风险缓解清单（红线与操作规范）**：

1. 完全免费，无广告、无内购、无付费解锁；捐助链接可放但要理解它提高了风险等级（Arena 2D 连捐助都不放，是最保守姿势）。
2. 代码 100% 原创；不复制任何官方游戏代码/引擎。
3. 不分发任何可独立使用的官方资产（不提供 ROM、不打包官方音乐；ROM 改造走 BPS 补丁模式）。
4. 页面显著位置放免责声明与权利归属，保留"收到通知 24 小时内下架"的承诺并真的能做到。
5. 商标描述性使用，标题加 "fan game/unofficial" 字样。
6. **架构级保险：素材层完全抽象、可整体替换**（见 5.4），随时可切换原创怪物包变身合规产品。
7. 不碰官方正在运营或即将发布的品类（TCG 对战、MOBA、Snap 等）。
8. 不在任天堂直面会/新作发售窗口做高调营销。
9. 署名素材链路上的社区来源（Showdown 素材库、PokeAPI 等）。
10. 预先写好《下架预案》：备用域名、社群转移方案（Discord 为大本营）、玩家存档导出。

### 4.3 团队与运营可行性：高（单人可做）

- 两个核心案例均为单人业余项目；PokéBonk 作者还公开承认使用了 AI 辅助开发（当前社区对此接受度已明显提高）。
- 运营减负机制已被验证：每周社区投票决定新增角色（内容排产交给社区）、任务系统替代人工运营活动、实时平衡 JSON 热更免发版。
- 需要的能力栈：TypeScript/Web 前端、一点游戏手感、Discord 社群运营、持续 6 个月以上的业余投入。最大的运营风险是**单人断更**，需在架构上让"内容更新"与"代码更新"解耦。

### 4.4 财务可行性：接近零成本

- 域名 ≈ 60 元/年；静态托管（Cloudflare Pages/Workers）免费额度足够；联机房间服务（如 Durable Objects/Colyseus 小实例）$5–20/月；素材与数据全部来自社区开源库，成本 0。
- 唯一大额投入是开发者时间（MVP 约 6–8 周全职等价工作量，见 5.6）。

## 五、技术分析

### 5.1 参考架构总览

```
┌────────────────────────── 浏览器（唯一客户端） ──────────────────────────┐
│  渲染层：Three.js(3D) 或 PixiJS/原生Canvas(2D)   ← 案例验证两条路都走得通 │
│  游戏循环：固定时间步长模拟 + 渲染插值（60Hz 模拟）                        │
│  ───────────────────────── 数据驱动分界线 ─────────────────────────       │
│  数据层：species.json / moves.json / typechart.json / balance.json        │
│  素材层：sprite 图集 / cries 音效（按全国图鉴编号组织，可整体替换）        │
└──────────────────────────────────────────────────────────────────────┘
            │ 可选轻后端（WebSocket 房间 / 排行榜 / 云存档 / 周投票）
            ▼
   Cloudflare Workers(Durable Objects) 或 Colyseus 小实例 + KV/Turso
```

要点：**数据层与素材层是整个方案的战略资产**——它们让游戏在"宝可梦模式"与"原创 IP 模式"之间一键切换。

### 5.2 技术栈选型

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **TypeScript + Vite + PixiJS/原生 Canvas（2D）** | 包体小、启动快、完全可控；Arena 2D 证明无引擎也能做 60FPS 竞技场 | 一切自建（场景图、动画、碰撞） | **推荐**（自走棋/卡牌/竞技场均适用） |
| TypeScript + Vite + Three.js（3D） | PokéBonk 实测路线（Vite+Three.js 已从其 JS 包验证）；2D billboard 方案美术成本极低 | 3D 手感与性能调校成本高 | 3D 割草类 |
| Godot 4（Web 导出） | 编辑器效率高、MIT 免费、可同时出桌面版 | Web 导出包体偏大（wasm ~30MB+），移动端加载体验差 | 桌面优先的项目 |
| Unity WebGL | 生态最全 | 包体大、加载慢、许可条款对同人灰色项目不友好 | 不推荐 |
| Phaser | 2D 全家桶最省事 | 抽象层在重度定制时会碍事 | 快速原型 |

**结论**：对单人开发者，**TS + Vite + PixiJS（2D 方向）** 是最优解；若执意 3D 割草，照抄 PokéBonk 的 Vite + Three.js + 2D billboard 路线。

### 5.3 素材与数据管线

| 资源 | 来源 | 说明 | 风险等级 |
|---|---|---|---|
| 精灵图（2D） | Pokemon Showdown 素材库（含动画帧）、PokeAPI sprites CDN（官方立绘/Gen5 动画 webp/Gen8 home） | PokéBonk 与 Arena 2D 的实际来源；按全国图鉴编号组织，方便管线自动化 | 中（版权仍属官方，社区惯例使用） |
| 叫声音效 | Showdown cries 库 / PokeAPI cries | 单声道短音频，体积小 | 中 |
| 数值数据 | PokeAPI JSON（种族值/招式/特性/属性表）、**@pkmn 系列 npm 包**（Showdown 数据与对战模拟的 TS 移植，MIT 协议） | 可直接生成棋子/角色面板与伤害公式 | 低（事实性数据） |
| 平衡先验 | Smogon 使用率与分级数据 | 冷启动平衡的好起点 | 低 |
| 3D 模型 | The Models Resource 等拆包站 | — | **高（任天堂对模型拆包更敏感，不建议）** |
| 音乐 | — | 官方音乐一律不用；用原创/AI 生成/免费库替代 | 官方音乐为高危项，禁用 |

**管线工艺**：素材下载脚本（按图鉴编号批量拉取）→ 去背/裁切 → 图集打包（free-tex-packer 或 TexturePacker CLI，输出 JSON+PNG/WebP）→ 按需加载（首屏只加载首发角色图集）。全流程脚本化，使得"整体替换素材包"是一次配置切换而非重做美术。

### 5.4 核心系统设计

**① 数据驱动与"可换皮"架构（最重要的设计决策）**

- 角色定义为纯数据（`species.json`：编号、属性、种族值→映射为移动速度/攻击/HP/资源上限、招式列表、被动、进化条件），渲染层只按数据实例化。
- 平衡数值单独成层（`balance.json`），并抄 PokéBonk 的作业：内置管理员平衡编辑器 + JSON 导入导出 + 一键发布，免发版调数值。
- 素材以 manifest 描述（编号→图集帧/音效/显示名），**切换 `manifest+pokemon-pack` 为 `manifest+original-pack` 即得到一个合法的商业化原创游戏**（参考 Brick Bronze → Loomian Legacy 的转型路径，但人家是重做美术，我们可以架构上预置好）。

**② 实时战斗内核（若选题含实时成分）**

- 固定时间步长（60Hz）模拟 + 渲染插值；实体-组件化组织。
- 招式状态机：`idle → windup(前摇) → active(判定帧) → recovery(后摇) → cooldown`——Arena 2D 已验证这套语汇能准确表达宝可梦招式。
- 判定原语四件套：弹道（projectile）、近战扇形（sweep）、圆形脉冲（pulse）、自身光环（aura），所有招式由原语组合。
- 双资源模型：HP + PP（即案例中"血量+体力值"），技能冷却与 PP 消耗双限制；状态异常以 tick 计时器实现。
- 手感三件套（PokéBonk 的设置面板直接印证其必要性）：hit-stop（命中停顿）、camera shake、命中闪白——开关式实现，参数可调。

**③ 数值系统：复用官方公式**

- 伤害公式、STAB、18×18 克制表、暴击、能力等级全部照搬官方世代公式（@pkmn/sim 有现成实现）——玩家的既有认知就是产品质量的一部分。
- 实时化映射规则要自洽：速度种族值 → 移动速度与冷却缩减；特防/防御 → 伤害减免；PP 上限 → 体力池。规则公开写在游戏内说明里，降低理解成本。

**④ 联机架构（按需选配）**

- Co-op PVE（PokéBonk 式 8 人房间码）：服务器权威 + WebSocket 广播，服务器驱动敌潮生成与按人数缩放；实现简单，作弊无感知。Cloudflare Durable Objects 天然适合"一房一对象"。
- 异步 PvP（自走棋推荐）：对战对手为云端阵容快照，**零实时同步需求**——单人开发者最该选的"联机"。
- 实时 1v1（Arena 2D 原版有）：需客户端预测/回滚，工期 +1 个月起，非首选项。

**⑤ 元游戏系统**

- 任务（日/周常）、排行榜（按模式分榜）、货币解锁角色（PokéBonk 的 BP 200–800 定价区间可参考）、每周社区投票（Discord 投票 → 数据驱动加角色，把内容排产外包给社区）。
- 游客模式优先：无账号先玩，账号只用于排行与云存档（降低传播摩擦）。

### 5.5 性能与兼容性

- 对象池 + 空间哈希网格做碰撞粗筛（百级同屏单位的下限要求）。
- 2D 图集合批；3D 路线则 billboard 合批 + 实例化绘制。
- 自动降分辨率 + 画质三档（PokéBonk 实测功能，弱核显机型友好）。
- 移动端：触屏虚拟摇杆、安全区适配、首包 < 5MB（首屏只含首发角色素材）。

### 5.6 工程量估算（单人，全职等价）

| 模块 | 工期 | 备注 |
|---|---|---|
| 技术底座（循环/渲染/输入/音频/场景） | 2–3 周 | PixiJS 可压缩到 1–2 周 |
| 战斗/规则内核（状态机/判定/资源/胜负） | 3–4 周 | 自走棋的战斗模拟器约 2 周 |
| 数值系统（数据接入/伤害公式/平衡工具） | 2 周 | 大量复用 @pkmn |
| 内容量产（24–44 角色 + 6 场地/棋盘） | 3–4 周 | 管线自动化后每角色 < 0.5 天 |
| 元游戏（任务/排行/投票/云存档） | 2–3 周 | 可后置到公测后 |
| 联机（异步 PvP 或 co-op 房间） | 2–4 周 | 异步 PvP 取下限 |
| 打磨（手感/特效/性能/触屏/多语言） | 2–3 周 | 不可省 |
| **合计** | **MVP（单机垂直切片）6–8 周；含联机与元游戏 3–4 个月** | |

**发布节奏建议**（抄案例的作业）：内部 Alpha（1 周，Discord 邀请制，即 PokéBonk 的"一周平衡性 Beta"）→ PokéCommunity/X 公开首发（带游客模式）→ 媒体素材包（GIF/短视频，方便 Dexerto 类栏目直接引用）→ 周更新 + 周投票进入长线运营。

## 七、结论与行动建议

**总体结论**：再选一个热门游戏用宝可梦素材改造，**技术上完全可行（单人、Web 栈、社区素材/数据供给成熟），传播上已被三连验证，法律上是"可管理的灰色地带"——必须以免费同人项目姿态运作，并把"可换皮"作为第一架构决策。**

**推荐选题**：自走棋/酒馆战棋 × 宝可梦（浏览器、中文首发差异化、异步 PvP、素材契合满格）；次选 Balatro 式肉鸽卡牌。

**三阶段路线图**：

1. **MVP（6–8 周）**：24 只角色、单模式、单机 + CPU、游客即玩、免责声明上线；Discord 开张。
2. **公测（+4–6 周）**：异步 PvP/排行榜/任务/周投票；PokéCommunity + X 首发，准备媒体 GIF；平衡热更工具上线。
3. **分岔决策点**：
   - 若收到权利方通知 → 24 小时内下架或按预案切换原创素材包；
   - 若数据验证玩法成立且想长期做 → 启动原创 IP 素材包（Loomian Legacy 路线），此时可上架 Steam 商业化——**先用车流验证玩法，再换引擎盖合规收费**。

**Go/No-Go 自检清单**：能否接受随时下架？能否坚持不接广告/内购？能否保证 6 个月周更？三个"是"则 Go。
